# 博客卡片悬浮样式优化准备

- 日期：2026-09-11
- 当前阶段：现有页面体验优化（博客列表页）
- 适用 Gate：改动范围、交互状态和发布验证已明确后，方可实施并发布

## 当前状态

博客列表卡片目前在鼠标悬浮或键盘聚焦时会整体变为深色、向上位移，同时封面图片放大。整体卡片变化较大，视觉上容易产生“翻盖”或整张卡片翻转的感觉。

## 本次目标

参考用户提供的飞书案例表达方式，但沿用 Leadtop 自身配色与字体：

1. 卡片保持“上方图片、下方文字”的稳定结构，不做翻转、透视或翻盖动画。
2. 悬浮和键盘聚焦时，封面图片不缩放，卡片本身不向上跳动。
3. 只让下方信息面板切换为 Leadtop 深蓝色，日期、分类和标题同步变为浅色。
4. 在图片与信息面板交界处的右侧显示白色圆形箭头，使用轻微透明度和位移动画提示可点击。
5. 手机端不依赖悬浮：保持内容清晰可读，并常驻显示尺寸更小的圆形箭头。

## 改动范围

- `app/blog/page.jsx`：调整卡片阅读入口的结构，以支持圆形箭头和无障碍文本。
- `app/blog/Blog.module.css`：修改列表卡片的静止、悬浮、键盘聚焦和手机端样式。
- 本准备文档及实施结果记录。

不修改文章详情页、首页模块、WordPress 内容、文章 URL、SEO 元信息、导航栏或其他卡片组件。

## 数据与回滚

实施前仅对上述两个前端源文件创建带时间戳的本地可恢复副本，存放在 `.codex-backups/`，不提交到 Git。Git 提交本身同时作为代码级回滚点。本次不涉及数据库或 CMS 数据写入。

## 验收标准

- 桌面端悬浮与键盘聚焦时，仅下方信息面板突出显示。
- 不存在卡片翻转、整体上移或图片放大效果。
- 圆形箭头位于图片与信息区交界附近，不遮挡标题和日期。
- 手机端卡片无需悬浮即可识别点击入口，且无横向溢出。
- 整张卡片仍为可访问的文章链接，键盘焦点清晰。
- 在 `/blog` 的桌面和约 390px 手机视口检查受影响区域，并运行 `git diff --check` 与一次最终构建。

## 实施顺序

1. 创建两个源文件的实施前备份并记录恢复方式。
2. 调整卡片阅读入口结构和局部样式。
3. 在本地博客列表页检查桌面悬浮、键盘焦点和手机布局。
4. 运行差异检查和最终构建。
5. 记录结果，在 `main` 提交并推送到 `origin/main`，随后检查线上博客列表页。
